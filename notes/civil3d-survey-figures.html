Civil 3D survey figure tips

How to keep figures, point groups and surfaces from turning into a mess, and how to fix them once they have.

Most Civil 3D survey headaches come from the same few places: figures nobody styled, point groups stacked in the wrong order, and every figure dumped into a surface as a breakline. None of it is hard to fix. It just has to be set up before the first import, not after the fortieth.

1. Let the figure prefix database do the work

Every figure name is matched against your figure prefix database (Prospector → Survey → Figure Prefix Databases). The prefix decides the figure's layer, style, whether it's a breakline, and which site it goes on. If a figure shows up on layer 0 with no style, it didn't match a prefix.

  • Use the same short codes your crew uses on the data collector: EP, TC, FL, BLDG, FNC.
  • Prefixes match the start of the name, so EP catches EP1, EP-N and EPX. Order matters if one code starts another (FL vs FLW).
  • Keep one database for the whole office and put it somewhere shared. One database per project is how standards drift.

2. Only real breaklines get the breakline flag

A breakline tells the surface "the ground changes slope sharply here." Edge of pavement, top and toe of slope, flowlines, curb: yes. Fences, building outlines, overhead utilities, tree lines: no. A fence surveyed at the top of a wall will quietly fold your surface into a ridge that isn't there.

Rule of thumb

If you'd be fine with the contours crossing the line, it isn't a breakline.

3. Give figures their own site

Objects on the same site interact. Figures that share a site with parcels or feature lines can split parcels and snap vertices to each other in ways you didn't ask for. Set the figure prefix to send figures to a dedicated Survey site, or to no site at all, and design work stays clean.

4. Point groups: order is everything

When a point is in more than one group, the group highest in the display order decides how it looks. That's why a control point sometimes shows up styled as a tree.

  • Keep _All Points at the bottom, with a plain or "none" style.
  • Put the most specific groups (Control, Monuments) at the top.
  • Build groups from raw descriptions or description keys, not hand-picked point numbers, so new imports drop into the right place.
  • Make a Ground Shots group for the surface that excludes what isn't ground: tops of walls, utility rims set high, tree trunks, overhead shots.

5. Linework codes: get them right in the field

The linework code set turns field codes into figures. The defaults use codes like B (begin), E (end), CLO (close) and curve codes. Whatever your set uses, print it on a card for the crew. Cleaning up linework in the office costs far more than coding it right on the shot.

  • Match the code set to the collector's feature codes so there's one language, not two.
  • When a figure goes wrong, fix the codes in the survey database and re-process linework. Don't just grip-edit the polyline.

6. The survey database is the source of truth

Points and figures in the drawing are copies of what's in the survey database. Edit them in the drawing and the next re-import or "insert into drawing" can overwrite your changes. Make fixes in the database, or deliberately break the link (for example by exploding figures into a separate drawing) once you're done with them.

7. A quick checklist before you build the surface

  1. Every figure has a style and a layer (none on layer 0).
  2. Only true breaklines are flagged.
  3. The surface uses the Ground Shots point group, not _All Points.
  4. Turn on the surface's crossing-breakline check and fix the hits.
  5. Look at the triangles along the edge. Long, skinny ones mean you need a boundary.
